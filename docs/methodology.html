Method

How the tiers are built

This page is a derived view of llm/specs/2026-08-29-fantasy-sports-platform-design.md in the repository, which is the design authority. Where the two disagree, that document wins.

Why ranks and not projections

Sources publish two things that are easy to conflate. A projection estimates points; a ranking orders players against each other. Most sites publish both, and many derive one from the other.

Projections carry a precision they do not have. A projection of 214.6 points invites arithmetic — differences, sums, replacement-level math — on a number whose real uncertainty band is tens of points wide. Draft rooms then act on differences that are noise.

The decision a drafter actually makes is ordinal: given what is on the board, who do I take, and can I wait? That is answered by an ordering and by the gaps in it.

So where a source publishes only projections, the pipeline sorts, assigns a within-position rank, and discards the projected value. Discarding rather than hiding is the point: a number kept "for reference" gets used — it leaks into tie-breaks, into value-over-replacement, and into the UI the moment someone wants one more column.

Where a tier break comes from

A naive tiering cuts wherever the gap between adjacent ranks is large. That over-reacts to noise at positions where sources disagree wildly, and under-reacts where they agree closely.

Instead, the step between two adjacent players is measured in units of how much the sources disagree about them:

separation(i) = (mean[i+1] − mean[i]) / sqrt((sd[i]² + sd[i+1]²) / 2 + ε)

A new tier opens where separation exceeds a threshold derived from that position's own separation distribution — median + k·MAD, not a global constant. The RB curve is nothing like the QB curve, and one threshold would mis-tier both.

The consequence worth stating plainly: disagreement narrows a break. If the sources cannot agree which of two players goes first, they are interchangeable and stay in one tier. A break survives only where the sources agree there is a real step down. On the board, the ± column is that spread.

With a single source every spread is zero and the formula degenerates, so the fallback is the raw gap normalized by the position's median gap — and the board says "single source" rather than "consensus", because it is not one.

Computed, then overridden — never replaced

The algorithm proposes breaks; a human accepts or overrides them. An override is recorded alongside the computed value, not in place of it, so the algorithm's error stays inspectable:

{ "position": "RB",
  "computed_breaks": [5, 12, 18],
  "accepted_breaks": [5, 14, 18],
  "note": "RB13 gap is a bye-week artifact" }

Player identity

Reconciling several sources is mostly an identity problem: name variants, suffixes, rookies with no prior-season row, players who changed teams. Every ingested row resolves to a canonical player ID before it is stored. Rows that do not resolve are written to a rejections file with a reason and retained — they are the input to extending the alias table, and they appear in every run report. Nothing is silently dropped.

The licence split

This repository is public on purpose. The primary rankings source is a paid subscriber product, and a personal subscription licenses one subscriber to use those rankings — not to republish them. Crediting the source does not change that: attribution is not a licence.

So the split runs along the licence boundary rather than the code/data boundary:

PublicPrivate
Ingestion and normalization code, identity resolution, the tiering algorithm, this site, the method, the governance Raw captures, normalized rows, and the rendered board built from a paid source — git-ignored, never committed

The cheat-sheet page fetches its dataset at runtime. On this public site that file is absent and the page falls back to a sample built from freely available consensus rankings. Run the same site locally with your own file in place and it renders your real board. The public artifact and the private artifact are the same code with different data — which is what makes the rule enforceable rather than aspirational.

Full reasoning: ADR-0001 and ADR-0002.

What this does not do

  • No point projections, and therefore no auction values or value-over-replacement — both need a point scale.
  • No source weighting yet. Weights need history to justify them, and guessing them is worse than not weighting at all.
  • No league management or platform syncing.
  • Information is genuinely lost at ingest: a source's view of how much better a player is survives only as a tier break. That is the trade being made, not an oversight.
